# 第 1 关：10 分钟跑通第一个窗口

> 本关目标：① 搭建 electron-vite + Vue3 + TypeScript 工程；② 理解 `electron.vite.config.ts` 三入口职责；③ 跑通 `pnpm dev` 热更新，通过预加载桥向渲染进程显示应用版本。

第 0 关讲完了选型和版本口径，这一关开始真正写代码。你会发现 Electron 的“Hello World”和普通 Vue 项目不一样：**它不是只有一个前端入口，而是主进程、预加载脚本、渲染进程三个入口要分别配置和构建。**

这就是我们这一关要跑通的效果。

## 二、核心概念：三入口与构建配置

Electron-vite 的核心是给 Electron 的三个进程分别提供 Vite 构建能力，配置集中在 `electron.vite.config.ts`：

| 入口 | 对应字段 | 输出目录 | 职责 |
|---|---|---|---|
| **主进程** | `main` | `dist/electron/main` | `app` 生命周期、`BrowserWindow`、原生 API |
| **预加载** | `preload` | `dist/electron/preload` | `contextBridge` 桥，向渲染进程暴露白名单 API |
| **渲染进程** | `renderer` | `dist/electron/renderer` | Vue3 界面，零 Node 权限 |

`package.json` 的 `main` 字段指向构建后的主进程入口：

```json
{
  "main": "./out/main/index.js"
}
```

> 注意：electron-vite 默认输出目录是 `out`（可通过 `build.outDir` 改为 `dist/electron/*`）。Electron 启动时的工作目录是输出目录，不是源码目录，因此源码可安全排除在打包产物之外。

## 三、代码实战

### 3.1 工程目录（主干骨架）

```
deskmind/
├── electron.vite.config.ts   # 三入口构建配置
├── package.json              # 依赖与脚本
├── tsconfig.json             # 根类型配置
├── tsconfig.node.json        # 主 / 预加载类型检查
├── tsconfig.web.json         # 渲染进程类型检查
├── index.html                # 渲染进程入口 HTML
├── shared/                   # 主 / 渲染共享类型与 IPC 通道常量
│   └── ipc.ts                # IPC_CHANNELS 白名单
├── src/main/
│   └── index.ts              # 主进程入口
├── src/preload/
│   └── index.ts              # 预加载脚本（contextBridge）
└── src/renderer/
    ├── main.ts               # Vue3 挂载
    ├── App.vue               # 根组件
    └── env.d.ts              # Vite 类型声明
```

### 3.2 主进程：`src/main/index.ts`

主进程负责创建窗口，并指定预加载脚本路径。注意 `webPreferences` 的安全默认值：

```ts
import { app, BrowserWindow, ipcMain } from 'electron'
import { join } from 'node:path'
import { isDev } from '@electron-toolkit/utils'

app.setName('DeskMind')

function createWindow() {
  const win = new BrowserWindow({
    width: 900,
    height: 670,
    show: false,
    autoHideMenuBar: true,
    title: 'DeskMind',
    webPreferences: {
      preload: join(__dirname, '../preload/index.js'),
      contextIsolation: true,   // 隔离预加载与渲染上下文
      nodeIntegration: false,   // 渲染进程禁用 Node
      sandbox: false            # 生产环境建议开启 true，本关先保持 false 以简化演示
    }
  })

  win.on('ready-to-show', () => {
    win.show()
  })

  if (isDev) {
    win.loadURL('http://localhost:5123/renderer')
  } else {
    win.loadFile(join(__dirname, '../renderer/index.html'))
  }
}

app.whenReady().then(createWindow)

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') {
    app.quit()
  }
})

/**
 * 白名单 IPC：渲染进程通过 preload 的 contextBridge 调用。
 * 所有渲染进程可触发的通道必须在此显式注册。
 */
ipcMain.handle('app:getVersion', () => app.getVersion())
```

### 3.3 预加载桥：`src/preload/index.ts`

预加载脚本通过 `contextBridge.exposeInMainWorld` 将白名单 API 暴露给渲染进程的 `window.electronAPI`。渲染进程**不能**直接访问 `ipcRenderer`，必须走这个桥：

```ts
import { contextBridge, ipcRenderer } from 'electron'
import { IPC_CHANNELS } from '@shared/ipc'

contextBridge.exposeInMainWorld('electronAPI', {
  getVersion: () => ipcRenderer.invoke(IPC_CHANNELS.APP_GET_VERSION)
})

export type ElectronAPI = {
  getVersion: () => Promise<string>
}

declare global {
  interface Window {
    electronAPI: ElectronAPI
  }
}
```

### 3.4 共享 IPC 通道：`shared/ipc.ts`

主 / 预加载 / 渲染三方共享通道常量，禁止裸字符串通道名：

```ts
export const IPC_CHANNELS = {
  APP_GET_VERSION: 'app:getVersion'
} as const

export type IPC_CHANNELS = typeof IPC_CHANNELS
```

### 3.5 渲染进程：`src/renderer/App.vue`

Vue3 组件通过 `window.electronAPI.getVersion()` 调用主进程能力，拿到应用版本并展示：

```vue
<script setup lang="ts">
import { ref, onMounted } from 'vue'

const version = ref<string>('')
const loading = ref(false)

onMounted(async () => {
  loading.value = true
  try {
    version.value = await window.electronAPI?.getVersion?.() ?? 'unknown'
  } catch {
    version.value = 'n/a'
  } finally {
    loading.value = false
  }
})
</script>

<template>
  <div class="app">
    <h1>DeskMind</h1>
    <p>Electron + Vue3 + TypeScript</p>
    <p v-if="loading">正在获取版本……</p>
    <p v-else>应用版本：{{ version }}</p>
  </div>
</template>

<style scoped>
.app {
  font-family: 'Helvetica Neue', PingFang SC, 'Microsoft YaHei', sans-serif;
  padding: 2rem;
}
h1 { font-size: 1.5rem; margin-bottom: 0.5rem; }
p { color: #666; }
</style>
```

## 四、踩坑指南

1. **`main` 字段必须指向构建后的主进程**：`package.json` 里的 `main` 是 `./out/main/index.js`（或你配置的输出目录），不是源码 `src/main/index.ts`。开发时 `electron-vite dev` 会处理这一点，但打包后必须保持一致。
2. **预加载路径用 `join(__dirname, ...)`**：主进程打包后工作目录变成输出目录，用 `__dirname` 拼接预加载脚本路径才可靠。
3. **渲染进程不能直接 import `electron`**：`nodeIntegration: false` 下渲染进程没有 `require('electron')`，所有系统能力必须通过 `window.electronAPI` 桥调用。
4. **不要写 `nodeIntegration: true` 省事**：这是 Electron 安全红线，一旦打开，渲染进程可直接执行任意 Node 代码，XSS 即可导致系统级攻击。
5. **dev 模式下窗口加载 `http://localhost:5123/renderer`**：这是 electron-vite 的默认开发地址，不要改成本地文件路径，否则 HMR 失效。

## 五、架构师视角：三进程模型的边界与运维成本

三进程模型是 Electron 的核心设计，也是桌面客户端架构评估的关键：

- **进程隔离带来的安全收益**：渲染进程运行在 Chromium 沙箱中，即使页面被攻破，攻击者也难以直接访问本地文件系统；所有敏感操作（读写文件、调用原生 API）必须经由主进程的 IPC 白名单审计。这是 Electron 能支撑生产级桌面应用的基础。
- **进程间通信的性能代价**：每次 `ipcRenderer.invoke` 都是跨进程同步/异步调用，高频细粒度通信（如每秒几十次的鼠标坐标上报）不适合走 IPC，应在渲染进程内处理，只在需要时上报。
- **内存与多窗口**：每个 `BrowserWindow` 默认对应一个渲染进程，多窗口应用内存占用会线性增长。需要在 `window-all-closed` 或窗口关闭时及时清理 `webContents` 监听器，避免泄漏。
- **版本升级的运维成本**：Electron 每 8 周一个 major，升级通常伴随 Chromium 和 Node.js 的同步升级，可能引入破坏性变更（如 `contextBridge` API 微调、Node ABI 变化导致原生模块需重编译）。生产环境建议锁定版本，并建立回归测试后再升级。

**一句话结论**：三进程模型用“进程隔离 + 受控 IPC”换取了桌面级的安全能力，代价是通信开销与内存占用高于单进程 Web 应用；架构设计时应把高频交互留在渲染进程，跨进程通信只用于必要的系统能力调用。
