## 一、为什么桌面客户端选 Electron

跨平台桌面方案主要有三类：Electron、Tauri、NW.js。对“用 Web 技术构建 mac / win / linux 客户端”这个目标，各自边界如下：

| 方案 | 核心原理 | 适合场景 | 潜在劣势 |
|---|---|---|---|
| **Electron** | Chromium + Node.js 双运行时，主 / 渲染两进程 | 功能丰富、生态成熟、需要原生能力（文件、系统托盘、自动更新）的桌面应用 | 包体积较大（通常 100MB+），内存占用高于原生 |
| Tauri | 系统 WebView + Rust 后端 | 对包体积、内存极度敏感的轻量应用 | 生态相对年轻，部分原生能力需自行绑定 Rust |
| NW.js | Chromium + Node.js 双运行时，渲染可直接调 Node | 从 Web 迁移成本极低的旧项目 | 进程模型较老旧，社区活跃度不如 Electron |

**本系列选 Electron**，理由是：DeskMind 主线 Demo 需要文件拖拽、系统托盘、全局快捷键、自动更新等原生能力，Electron 的生态和文档在这些场景上最成熟；且前端团队已有 Vue3 / TypeScript 积累，无需学习 Rust。

## 二、核心设计：三进程模型

理解 Electron，最关键的一句话是：**一个 Electron 应用有三个进程，职责必须分开。**

| 进程 | 运行环境 | 负责什么 | 典型能力 |
|---|---|---|---|
| **主进程 (Main)** | Node.js | 应用生命周期、窗口管理、原生系统 API | `app`、`BrowserWindow`、`ipcMain`、`Menu`、`Tray`、`autoUpdater` |
| **预加载脚本 (Preload)** | Node.js + 渲染 DOM | 主进程与渲染进程的安全桥 | `contextBridge.exposeInMainWorld`，只暴露白名单 API |
| **渲染进程 (Renderer)** | Chromium (浏览器) | 界面渲染、用户交互 | Vue3 应用、Pinia 状态、零 Node 权限 |

**安全默认值**（系列红线，不可破）：

- `contextIsolation: true` —— 隔离预加载与渲染上下文，防止渲染进程篡改预加载对象。
- `nodeIntegration: false` —— 渲染进程不能直接使用 Node 模块，所有系统能力必须走预加载桥。
- `sandbox: true` —— 进一步限制渲染进程的系统访问能力（视需求开启）。

能力是“经由预加载暴露”给渲染进程的，不是直接给渲染进程 Node 权限。

## 三、架构师视角：选型评估清单

如果你是在做技术选型，而不是马上写代码，可以用下面这张表快速判断 Electron 是否匹配你的场景：

| 评估维度 | Electron 的答案 | 需要确认的边界 |
|---|---|---|
| 跨平台形态 | 单套代码产出 dmg / exe / AppImage / deb | 三平台签名与公证策略不同，macOS 公证最复杂 |
| 包体积 | 通常 100MB+（自带 Chromium） | 用户是否能接受较大的首次下载 |
| 内存占用 | 每窗口一个渲染进程，基础占用较高 | 多窗口场景需注意内存泄漏与进程清理 |
| 原生能力 | 完整 Node.js + Electron 原生 API | 文件系统、系统托盘、全局快捷键均可直接调用 |
| 安全边界 | 渲染进程沙箱化，通过预加载桥暴露白名单 | 不可信内容必须通过 IPC 校验，禁止裸 `nodeIntegration: true` |
| 自动更新 | `electron-updater` 支持三平台 | Linux 通常需自建更新源，macOS 需签名与公证 |
| 运维成本 | 需要维护 Electron 版本升级（每 8 周一个 major） | 官方仅支持最近 3 个稳定 major，旧版会停止安全修补 |

**一句话结论**：如果你的目标是“用 Web 技术快速产出功能完整的三平台桌面客户端，且能接受一定的包体积与内存开销”，Electron 是当前最成熟的选择；如果包体积和内存是硬性约束，应优先评估 Tauri。

## 四、动手前必看：版本口径

Electron 生态最大的坑是**版本漂移**：Electron 每 8 周一个 major 版本，官方只支持最近 3 个稳定 major，旧版会停止安全修补，且可能丢弃对旧操作系统的支持。

| 口径 | 来源 | 锁定版本（2026-11 写作时） | 用途 |
|---|---|---|---|
| Electron 稳定版 | `releases.electronjs.org` | **45.x** | 所有 Electron API 的唯一依据 |
| Node.js | electron-vite 官方要求 | **20.19+ / 22.12+** | 构建环境 |
| electron-vite | `electron-vite.org` | **6.x** | 构建工具（主 / 预加载 / 渲染三入口） |
| Vite | electron-vite 要求 | **8.x** | 打包底座 |
| Vue / TypeScript | npm | **Vue 3.5.x / TS 5.x** | UI 与类型 |
| electron-builder | `electron.build` | **26.x** | dmg / exe / AppImage / deb 产物 |

**统一表述**：本系列锁定一套版本，以仓库 `package.json` + lockfile 为准；每篇文章开头注明锁定的 Electron 版本与最低 OS（Windows 10+、macOS 10.15+、Linux glibc 2.31+ 为常见底线，最终以锁定版本的官方平台表确认）。凡涉及版本差异的 API，一律以锁定版本文档为准，不写“最新版”这种模糊说法。
